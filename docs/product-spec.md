# Aster Desktop — MVP v2 Product Specification

**Status:** Normative baseline

**Target platform:** Windows 11

**Specification version:** 2.0

**Last updated:** 2026-07-13

**Implementation status:** This document specifies the intended MVP v2 outcome. It does not assert that the implementation, a package, or any acceptance gate passes.

## 1. Product intent

`PR-001` — **Retired for MVP v2.** This identifier described the MVP v1 Z.AI-only `glm-5.1` product. Its historical acceptance evidence remains valid only for that scope. `PR-004` supersedes it.

`PR-002` defines Aster as a real desktop client, not a website containing an API key. Tauri/Rust owns credentials, external provider access, persistence, validation, usage accounting, and cancellation. React/TypeScript owns presentation and user interaction.

`PR-003` defines success as a complete, dependable chat lifecycle: configure securely, create a conversation, stream and stop a response, persist locally, recover after restart, revise or regenerate, and safely import or export a conversation.

`PR-004` defines MVP v2 as a direct, curated multi-provider desktop client. A selectable model must have a dated, verified, official provider-hosted inference endpoint and a complete implemented contract. A requested name that does not meet that bar is absent from the catalog rather than displayed as unavailable.

`PR-005` defines transparent, non-transactional usage support. Aster reports locally observed token metadata, allows an advisory per-provider seven-day budget, reads an exact provider balance only where a documented read-only endpoint exists, and delegates every credit or plan action to the provider's website in the default browser.

## 2. Intended user and primary journey

The primary user is a Windows 11 developer, analyst, or security practitioner who has their own account and API key for one or more catalog providers and wants focused local chat history.

The golden path is:

1. Launch the installed desktop application.
2. Choose a provider and model from the verified catalog.
3. Read the provider-specific external-processing notice, including the fixed US-region notice for Alibaba Cloud, and save that provider's API key through the Rust-owned native Windows credential prompt.
4. Start a new chat and choose Fast, Standard, or Deep when that profile is supported by the selected model.
5. Watch the response arrive incrementally, or stop it.
6. Review the locally observed seven-day token totals and configure an advisory provider budget.
7. Refresh DeepSeek balance explicitly, or open another provider's account website to check balance, add credits, or change a plan.
8. Copy, edit and resend, regenerate, restart without losing completed history, and safely import or export a conversation.

## 3. Release profiles

| Profile      | Purpose              | Provider behavior                                                                      | Persistence                 | Secrets                                         |
| ------------ | -------------------- | -------------------------------------------------------------------------------------- | --------------------------- | ----------------------------------------------- |

Output caps are application policy. `reasoning_content`, thought traces, or equivalent hidden reasoning are discarded and are never displayed, persisted, logged, exported, or replayed.

## 6. Data and lifecycle rules

- A conversation has an opaque ID, title, provider ID, exact model ID, response profile, created timestamp, and updated timestamp.
- Provider/model may change only while the conversation contains no message. The backend, not UI state, enforces the lock.
- A message has an opaque ID, conversation ID, role, content, created timestamp, terminal status, optional validated `inputTokens`, `cachedInputTokens`, `outputTokens`, and `totalTokens` fields, and a typed finish reason where applicable. Input and cached input are disjoint; unknown usage remains unknown. A newly completed assistant response records `stop` or `outputLimit` from the verified adapter terminal; a completed legacy/imported assistant response without authoritative evidence records `unknown`; other roles/statuses have no finish reason.
- A local usage observation contains only an opaque operation identity, provider/model, UTC completion timestamp, optional validated token counts, and a partial-data flag. It contains no prompt, response, title, credential, provider payload, or balance. It is idempotent and independent of conversation deletion because provider consumption already occurred. Observations older than the trailing seven-day product window may be pruned transactionally.
- A per-provider token budget is local configuration in SQLite. It is not a provider quota, monetary balance, authorization decision, or request limit.
- A provider disclosure acknowledgement stores only provider ID and disclosure version. A version mismatch blocks that provider send until the new English notice is accepted; it is not blanket consent for another provider.
- A refreshed DeepSeek balance is held in Rust memory only for the current application session. It includes the provider's returned availability, currency-denominated balance values, and observation time; it is never derived or persisted.
- `streaming` and `stopping` are ephemeral runtime/UI states. Persisted assistant statuses remain `complete`, `cancelled`, or `error`.
- Timestamps are stored in UTC and rendered using the user's locale. The seven-day window is the instant from `now - 7 days` through `now`, not a provider billing cycle.
- Export version 2 includes provider/model, the typed completed-assistant finish reason, and optional per-message usage breakdown. It excludes the local budget, aggregate usage observations, balance, credentials, configuration, paths, headers, logs, hidden reasoning, and source IDs.

## 7. Explicitly out of scope for MVP v2

- Arbitrary provider URLs, user-entered model IDs, remote model discovery, aggregators, provider plugins, and unavailable catalog placeholders.
- In-app purchases, credit-card entry, plan changes, automatic top-up, price estimation, cost forecasting, or enforcement of provider limits.
- Automatic/background balance polling or any provider balance endpoint other than the documented DeepSeek read-only endpoint.
- Production deployment of NVIDIA NIM; the catalog entries use the hosted prototype service only.
- Projects, attachments, local indexing/RAG, model-invoked tools, function calling, shell/process execution, arbitrary filesystem access, voice, cloud sync, and multi-user access control.
- Full-message search, provider-powered search, context summarization, or prompt templates. The local title filter in `FR-019` remains in scope.
- Automatic updates until a verified signed update chain and rollback plan exist.

## 8. Constraints and assumptions

- The user supplies a legitimate credential and accepts each selected provider's terms, region, data handling, cost, availability, and model-specific limitations.
- Alibaba Cloud catalog traffic is fixed to the US-region endpoint; Aster does not choose a region dynamically.
- Local token observations may be incomplete and are not authoritative billing records. Provider token semantics may differ and are displayed without pretending they are interchangeable monetary units.
- The client cannot guarantee provider quality, truthfulness, retention, availability, latency, balance accuracy, or policy behavior.
- Local history is plaintext protected by Windows account and filesystem controls; application-level database encryption is not claimed.
- An unsigned artifact is an engineering build, not a production release.

## 9. Acceptance and change control

The MVP v2 outcome is accepted only under [acceptance-criteria.md](acceptance-criteria.md). Any catalog change requires a dated official-contract update, threat review, ADR review, exact request/response fixtures, and a new catalog version before implementation. Removing a provider/model must preserve existing local history and define import/export compatibility; adding an unverified placeholder is prohibited.
