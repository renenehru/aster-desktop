# Aster Desktop — Security and Privacy Requirements

**Status:** Normative baseline

**Applies to:** Source, tests, local data, CI, packages, installers, updates, and documentation

**Last updated:** 2026-07-12

**Implementation status:** These are mandatory controls, not claims of implementation or verification.

## 1. Security objectives

The MVP protects the user's provider credential, prevents model or imported content from becoming executable authority, limits the desktop application's privileges, keeps local conversation handling explicit, and makes release integrity demonstrable. Security claims require evidence; absence of a finding is not proof of a control.

Security priorities are:

1. API-key confidentiality and strict backend custody.
2. Integrity of the application, requests, local history, and release artifacts.
3. Safe rendering and parsing of hostile provider/imported content.
4. Least-privilege IPC, OS permissions, networking, and filesystem access.
5. Availability through bounded processing, cancellation, recovery, and safe failures.
6. User knowledge and control over external processing and plaintext export.

## 2. Data handling policy

| Data class              | Examples                                                    | Storage                                       | Permitted transmission                          | Logging                          |
| ----------------------- | ----------------------------------------------------------- | --------------------------------------------- | ----------------------------------------------- | -------------------------------- |
| Secret                  | Z.AI API key, authorization header                          | Windows credential store only                 | Z.AI over validated HTTPS from Rust             | Never                            |
| Sensitive user content  | Prompts, responses, titles, imported/exported conversations | User-scoped SQLite; explicit plaintext export | Z.AI after user send; user-selected export path | Never                            |
| Sensitive metadata      | Message times, model/mode, usage metadata                   | SQLite                                        | Minimum needed provider fields                  | No direct identifiers or content |
| Safe application errors | Stable code, bounded user message, retryable flag           | Not persisted by Aster v1                     | IPC to the main webview only                    | No application logging           |
| Public application data | Static UI copy, schema name/version                         | Package/configuration                         | As needed                                       | Allowed                          |

Local SQLite history is not claimed to be encrypted by the application. Windows user-account and filesystem protections are relied upon in v1, and the UI must describe local persistence accurately. Device compromise, an already-unlocked hostile user session, and provider-side retention are residual risks rather than controls the client can eliminate.

## 3. Normative requirements

### 3.1 Credential and secret management

| ID        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Required verification                                                                          |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `SEC-001` | An 8–255-byte printable-ASCII provider API key **MUST** be captured only by a Rust-owned native Windows credential prompt, never silently truncated, held in the Rust process for the minimum practical lifetime, and stored through the Windows credential-store adapter under an application-specific target. A full 256-character native result **MUST** be rejected as potentially truncated. The key **MUST NOT** enter the webview, an IPC payload, SQLite, browser storage, preferences, source, fixtures, packaged environment files, or exports. | Native prompt boundary/adapter integration test; IPC/DOM/database/export/package sentinel scan |
| `SEC-002` | The webview **MUST NOT** render a credential input or receive the API key in frontend state, DOM, command arguments, results, events, status, errors, or debug representations. It may receive only configured/not-configured state.                                                                                                                                                                                                                                                                                                                      | Command inventory and IPC contract test; DOM/frontend/package sentinel scan                    |
| `SEC-003` | Authorization headers and secret-bearing values **MUST** be redacted before formatting or logging and released from memory as soon as practical. Errors **MUST NOT** embed the key.                                                                                                                                                                                                                                                                                                                                                                       | Unit tests with sentinel secrets across success/error/debug paths; log scan                    |
| `SEC-004` | The no-secret-argument credential command **MUST** open the native prompt; a confirmed value **MUST** replace the prior credential safely, cancellation **MUST** be a no-op, and removal **MUST** delete the credential-store entry. Only status may return to the webview.                                                                                                                                                                                                                                                                               | Windows native-prompt/adapter integration test with isolated test target                       |
| `SEC-005` | Browser demo mode **MUST NOT** display a credential input, invoke credential APIs, use a real provider endpoint, or persist a secret.                                                                                                                                                                                                                                                                                                                                                                                                                     | Browser bundle/configuration test and E2E inspection                                           |

### 3.2 Network and provider boundary

| ID        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Required verification                                                                               |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `SEC-006` | Provider requests **MUST** originate in Rust and target only the application-owned exact HTTPS Z.AI origin and documented chat-completions path. IPC, conversation content, imports, and configuration **MUST NOT** override the origin, path, proxy, or authorization header.                                                                                                                                                                                                                                                                                                                                     | Unit/contract tests with hostile URL/header inputs; Tauri capability review                         |
| `SEC-007` | TLS hostname and certificate-chain validation **MUST** remain enabled. Accept-all certificates, hostname bypasses, plaintext HTTP, and shipped custom trust bypasses are prohibited.                                                                                                                                                                                                                                                                                                                                                                                                                               | Static/configuration assertion; controlled invalid-certificate test                                 |
| `SEC-008` | Provider calls **MUST** have explicit connection, response/idle, and overall bounds. Retries **MUST** be bounded, jittered, honor provider retry guidance where valid, and never automatically retry authentication failures or replay after content was surfaced.                                                                                                                                                                                                                                                                                                                                                 | Fake-server timing/retry contract tests                                                             |
| `SEC-009` | Request bodies **MUST** contain exactly the approved MVP keys: relevant `user`/`assistant` `messages`, `model: "glm-5.1"`, `stream: true`, the verified `thinking.type` mapping, and the application-owned `max_tokens` cap. `thinking.clear_thinking` **MUST** be omitted, relying on its documented `true` default; preserved thinking **MUST NOT** be enabled. Temperature, tools, system/tool messages, `reasoning_effort`, `enable_thinking`, `stream_options`, and caller-selected fields are excluded. `reasoning_content` **MUST NOT** be requested for display, replayed, logged, persisted, or exported. | Exact request-key/snapshot contract tests for all modes; response/database/log/export sentinel scan |
| `SEC-010` | SSE parsing **MUST** enforce the architecture section 7.1 limits on header/body, buffered line, event, delta, total response content, and duration; **MUST** fail on the first malformed or unsupported event; and **MUST** apply the exact documented finish-reason mapping without executing tools or exposing raw provider data.                                                                                                                                                                                                                                                                                | Boundary and finish-reason tests, adversarial fixture corpus, fuzz/property tests                   |
| `SEC-011` | Cancellation **MUST** abort the backend network operation, terminalize the persisted message once, and reject late, duplicate, out-of-order, or cross-request deltas.                                                                                                                                                                                                                                                                                                                                                                                                                                              | Integration tests for cancellation and event races                                                  |

### 3.3 Webview, rendering, and navigation

| ID        | Requirement                                                                                                                                                                                                                                                                     | Required verification                                                             |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `SEC-012` | The packaged application **MUST** enforce a restrictive Content Security Policy with no `unsafe-eval`, no arbitrary remote script, and only the origins/directives necessary for packaged UI operation.                                                                         | Packaged configuration test and CSP policy assertion                              |
| `SEC-013` | Runtime JavaScript, CSS, fonts, analytics, frames, plugins, and other active content **MUST NOT** be loaded from remote origins. Production source maps **MUST NOT** disclose sensitive build paths or secrets.                                                                 | Bundle inventory; CSP test; packaged artifact scan                                |
| `SEC-014` | Raw HTML in Markdown **MUST** be disabled or removed, and the final rendered tree **MUST** pass an allowlist sanitizer immediately before any HTML sink. Script, handler, form, embedded-content, dangerous SVG/MathML, style, and scriptable attributes are denied by default. | Component tests with OWASP-style XSS corpus and sanitizer configuration assertion |
| `SEC-015` | Links derived from model/imported content **MUST** accept only approved protocols, display their destination, and open with safe external navigation. `javascript:`, `data:`, `file:`, custom command, and Tauri IPC schemes from content **MUST** be rejected.                 | Protocol matrix tests; E2E external-link test                                     |
| `SEC-016` | Copy actions **MUST** copy text rather than executable markup and **MUST NOT** automatically execute, paste, save, or transmit copied content.                                                                                                                                  | Component/E2E clipboard tests                                                     |

### 3.4 IPC, authorization, and application state

| ID        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Required verification                                                                                                                      |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `SEC-017` | The Tauri command and event surface **MUST** be allowlisted, typed, and restricted to the main application window. Wildcard shell, process, filesystem, URL, and network capabilities are prohibited.                                                                                                                                                                                                                                                                                                   | Capability snapshot test; command inventory review                                                                                         |
| `SEC-018` | Every application-defined webview command **MUST** use a raw UTF-8 JSON byte body. Rust **MUST** reject Tauri's pre-deserialized JSON invoke form for those commands, enforce the 320-KiB raw ceiling before parsing, and then enforce nesting, per-command keys, type, enum, identifier, semantic size, and state. Frontend checks are usability controls and **MUST NOT** be the sole enforcement. Exact Tauri window/event capabilities remain framework-owned and carry no application data object. | Raw application-IPC boundary tests for oversize, malformed, deep, unknown, wrong-type, and invalid-state inputs; core capability inventory |
| `SEC-019` | One active generation is allowed per conversation, and state transitions **MUST** be enforced in Rust. Request/conversation/message IDs **MUST** bind events to the originating operation.                                                                                                                                                                                                                                                                                                              | State-machine property tests and concurrent integration tests                                                                              |
| `SEC-020` | Errors crossing IPC **MUST** use stable safe codes and bounded user messages. Raw provider bodies, SQL, stack traces, credential values, and full local paths **MUST NOT** cross the boundary.                                                                                                                                                                                                                                                                                                          | Sentinel/error-path contract tests                                                                                                         |
| `SEC-021` | Deferred projects, attachments, tools, shell commands, and arbitrary filesystem features **MUST NOT** register backend handlers or permissions in MVP v1.                                                                                                                                                                                                                                                                                                                                               | Command/capability inventory negative assertion                                                                                            |

### 3.5 Storage, lifecycle, import, and export

| ID        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Required verification                                                                     |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `SEC-022` | SQLite access **MUST** use parameterized statements, foreign keys, bounded fields, terminal status enums, and transaction-safe migrations. Credentials, headers, hidden reasoning, raw provider traces, and ephemeral `streaming`/`stopping` states **MUST NOT** enter the database.                                                                                                                                                                                             | Repository/migration tests; status-enum and sentinel database inspection                  |
| `SEC-023` | The database **MUST** be created under the application data area with current-user permissions. Aster v1 **MUST NOT** create an application diagnostic log and **MUST NOT** silently destroy or replace a corrupt database.                                                                                                                                                                                                                                                      | Windows integration test, filesystem inventory, and recovery-path test                    |
| `SEC-024` | Import **MUST** validate the exact versioned allowlist schema in architecture section 9 plus the numeric file, collection, nesting, and field limits in section 7.1 before mutation. The 32-MiB file ceiling **MUST** be enforced both before and during bounded reading. Unknown fields, source/local IDs, `conversationId`, derived counts, credentials, configuration, internal paths, unsupported models/roles/statuses, and executable interpretation **MUST** be rejected. | Import abuse corpus, bounded-read tests, and exact-schema tests                           |
| `SEC-025` | Import **MUST** be atomic: any validation or database failure leaves the pre-import database unchanged, and imported identifiers are remapped by the backend.                                                                                                                                                                                                                                                                                                                    | Transaction rollback/invariant tests                                                      |
| `SEC-026` | Desktop import/export file selection **MUST** use Rust-owned native open/save dialogs. React **MUST NOT** provide a path or serialized file payload for privileged desktop I/O, and user-controlled names or document fields **MUST NOT** be concatenated into a path. Browser-demo picker/download behavior is presentation-only and does not satisfy this control.                                                                                                             | Rust dialog-adapter integration tests, IPC negative assertions, and path traversal corpus |
| `SEC-027` | Export **MUST** include only the versioned conversation schema, **MUST** exclude secrets/configuration/internal paths, and **MUST** warn that the file contains plaintext conversation content. Serialization **MUST** stop at the 32-MiB ceiling before opening the native save dialog or writing.                                                                                                                                                                              | Golden export and size-bound tests, sentinel scan, E2E warning test                       |
| `SEC-028` | Conversation deletion **MUST** require deliberate confirmation, be transactional, remove child messages, and never delete unrelated conversations.                                                                                                                                                                                                                                                                                                                               | Repository and E2E deletion tests                                                         |

### 3.6 Privacy, consent, and diagnostics

| ID        | Requirement                                                                                                                                                                                                                                                                                                                                             | Required verification                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `SEC-029` | Before the first provider request, the user **MUST** receive a visible external-processing notice. A send action is the explicit trigger for transmitting that conversation context; browsing local history is not.                                                                                                                                     | Clean-profile E2E test and network observation                                     |
| `SEC-030` | The client **MUST** minimize provider context to supported relevant messages and **MUST NOT** transmit unrelated conversations, local files, local paths, logs, or device inventory.                                                                                                                                                                    | Request-body contract tests with sentinel unrelated data                           |
| `SEC-031` | MVP v1 **MUST NOT** create application diagnostic logs or upload telemetry, analytics, or crash reports. IPC errors contain only a stable code, bounded safe message, and retryable flag; prompts, responses, titles, local filter queries, imports, exports, keys, headers, URLs, paths, database details, and direct user identifiers are prohibited. | Filesystem/network negative assertions; IPC error sentinel tests; bundle inventory |
| `SEC-032` | The UI **MUST** disclose that conversation history is stored locally without claiming application-level database encryption, and **MUST** provide explicit export and delete actions.                                                                                                                                                                   | UI copy review and E2E verification                                                |

### 3.7 Supply chain, CI/CD, and release integrity

| ID        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Required verification                                                                                |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `SEC-033` | JavaScript and Rust dependency resolution **MUST** be locked and lockfile changes reviewed. New runtime dependencies require purpose, maintenance, license, provenance, and transitive-risk review.                                                                                                                                                                                                                                                                                                              | Lockfile presence/diff review and dependency inventory                                               |
| `SEC-034` | CI **MUST** run formatting, type/lint, tests, Rust `clippy` with warnings denied, static analysis where configured, dependency vulnerability/policy checks, and secret scanning. | `SEC-036` | Known exploitable high or critical vulnerabilities **MUST** block production release unless a documented, owned, time-bounded exception includes compensating controls and expiry.                                                                                                                                                                                                                                                                                                                               | Vulnerability report plus exception registry review                                                  |
| `SEC-037` | Production binaries/installers **MUST** be signed by the authorized Windows code-signing identity and verified after packaging. | `SEC-038` | Automatic updates **MUST** remain disabled until update metadata/artifacts are signed, verification rejects tampering, rollback/recovery is tested, and the update origin is allowlisted.                                                                                                                                                                                                                                                                                                                        | Configuration assertion and signed-update negative/positive tests                                    |
| `SEC-039` | Production packages and source archives **MUST NOT** include real secrets, private test data, development endpoints, debug bypasses, writable runtime scripts, remotely fetched executable code, or ignored/untracked workspace content. A shared source archive **MUST** be generated from an identified clean commit with `git archive` or an equivalently strict tracked-file allowlist; directory-wide archiving with a denylist is prohibited.                                                              | Package/archive inventory, secret scan, binary/config review, tracked-file comparison                |

## 4. Verification environments

| Environment        | Allowed secrets                                 | External provider                       | Security evidence value                        |
| ------------------ | ----------------------------------------------- | --------------------------------------- | ---------------------------------------------- |
| Unit/component     | None; fake sentinels only                       | No                                      | Pure logic and rendering controls              |
| Integration        | Isolated fake credential target; fake sentinels | Local fake SSE server                   | IPC, credential, storage, parser, cancellation |
| Browser demo       | None                                            | No                                      | Visual/accessibility behavior only             |
| Windows E2E        | Ephemeral scoped test credential                | Fake by default; explicit live job only | Desktop lifecycle and OS integration           |
| Release validation | No embedded secret                              | Network only if explicit test plan      | Package, policy, SBOM, signature, provenance   |

A real provider key may be supplied only by a protected CI secret or user at runtime to an explicitly selected live-contract test. It must be masked, minimally scoped if the provider supports scope, and never available to untrusted pull-request code.

## 5. Security gate policy

Each required control reports `PASS`, `FAIL`, or `NOT RUN` with a source revision and evidence location. `NOT RUN` includes unavailable tools, unavailable Windows host, missing signer, missing SBOM, or missing evidence. For a production release, any required `FAIL` or `NOT RUN` blocks the release.

An engineering MVP build may be delivered for local evaluation with explicitly reported production-only gates not run, particularly installer signing, but it may not be called signed, hardened, production-ready, or generally distributable. Runtime controls protecting credentials and data are not waivable merely because the build is an engineering build.
